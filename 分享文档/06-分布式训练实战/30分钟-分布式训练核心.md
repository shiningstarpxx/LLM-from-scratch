# Part 1: 为什么需要分布式？

---

## 单卡的局限

```
训练7B模型需要: 112-160GB
A100显存: 80GB

单卡放不下!

更大的模型:
- 70B: 需要 ~1TB
- 175B: 需要 ~3TB
```

---

## 分布式的目标

```
1. 内存: 多卡分摊，放下大模型
2. 速度: 并行计算，缩短训练时间
3. 容错: 单卡故障不影响整体
```

# Part 2: 数据并行基础

---

## 2.1 核心思想

```
每张卡:
- 持有完整模型副本
- 处理不同batch的数据
- 计算梯度后同步

┌─────────┐ ┌─────────┐ ┌─────────┐
│  GPU 0  │ │  GPU 1  │ │  GPU 2  │
│ Model   │ │ Model   │ │ Model   │
│ Data[0] │ │ Data[1] │ │ Data[2] │
└────┬────┘ └────┬────┘ └────┬────┘
     │           │           │
     └─────────┬─────────────┘
               │
         All-Reduce梯度
               │
     ┌─────────┴─────────────┐
     │      同步更新          │
     └───────────────────────┘
```

---

## 2.2 PyTorch DDP

```python
import torch.distributed as dist
from torch.nn.parallel import DistributedDataParallel as DDP

# 初始化
dist.init_process_group(backend='nccl')
local_rank = int(os.environ['LOCAL_RANK'])
torch.cuda.set_device(local_rank)

# 包装模型
model = YourModel().cuda()
model = DDP(model, device_ids=[local_rank])

# 训练 (和单卡几乎一样!)
for batch in dataloader:
    loss = model(batch)
    loss.backward()  # DDP自动同步梯度
    optimizer.step()
```

---

## 2.3 All-Reduce通信

```
Ring All-Reduce: 高效梯度聚合

Step 1: 每卡发送1/N给下一卡
Step 2: 累加并继续传递
...
Step 2N: 所有卡都有完整结果

通信量: 2 × (N-1)/N × P ≈ 2P
(P是参数量，与卡数N无关!)
```

---

## 2.4 数据并行的问题

```
8卡训练7B:

每卡存储:
- 模型参数: 14GB
- 梯度: 14GB
- Adam状态: 56GB
- 总计: 84GB

8卡总共: 84 × 8 = 672GB
实际需要: 只有84GB

冗余: 8倍!

这就是ZeRO要解决的问题
```

# Part 3: ZeRO: 消除冗余

---

## 3.1 ZeRO三阶段

```
┌──────────────────────────────────────────┐
│ Stage   分片内容              内存节省   │
├──────────────────────────────────────────┤
│ ZeRO-1  优化器状态            4x         │
│ ZeRO-2  + 梯度                8x         │
│ ZeRO-3  + 参数                N倍 (N=卡数)│
└──────────────────────────────────────────┘
```

---

## 3.2 ZeRO-1: 分片优化器状态

```
标准DP (8卡):
每卡: 模型14GB + 梯度14GB + Adam 56GB = 84GB

ZeRO-1:
每卡: 模型14GB + 梯度14GB + Adam 56GB/8 = 35GB

内存减少: 84 → 35 GB (58%减少)
```

---

## 3.3 ZeRO-2: + 分片梯度

```
ZeRO-2:
每卡: 模型14GB + 梯度14GB/8 + Adam 56GB/8 = 23GB

内存减少: 84 → 23 GB (73%减少)
```

---

## 3.4 ZeRO-3: + 分片参数

```
ZeRO-3:
每卡: 模型14GB/8 + 梯度14GB/8 + Adam 56GB/8 = 10.5GB

内存减少: 84 → 10.5 GB (88%减少!)

代价: 需要All-Gather参数
通信量增加 ~50%
```

---

## 3.5 ZeRO-3工作流程

```python
# 前向传播
for layer in model.layers:
    # 1. All-Gather本层参数
    params = all_gather(layer.params_shard)

    # 2. 计算
    output = layer(input, params)

    # 3. 释放非本分片参数
    release(params_not_mine)

# 反向传播类似，还需要Reduce-Scatter梯度
```

import deepspeed

config = {

# Part 4: 模型并行简介

---

## 4.1 什么时候需要？

```
数据并行 + ZeRO-3 仍放不下?
→ 需要模型并行

典型场景:
- 单层参数 > 单卡容量
- 超大FFN层 (如MoE的专家)
```

---

## 4.2 张量并行 (TP)

```
切分单层内的矩阵

Y = X @ W

W切分为 [W1, W2]:
GPU 0: Y1 = X @ W1
GPU 1: Y2 = X @ W2
合并: Y = [Y1, Y2]

通信: 每层2-4次All-Reduce
适合: 高带宽连接 (NVLink)
```

---

## 4.3 流水线并行 (PP)

```
按层切分模型

GPU 0: Layer 0-7
GPU 1: Layer 8-15
GPU 2: Layer 16-23
GPU 3: Layer 24-31

数据像流水线流动:
[batch0] → GPU0 → GPU1 → GPU2 → GPU3

问题: Pipeline bubble (GPU空闲时间)
解决: Micro-batch
```

---

## 4.4 3D并行

```
大模型标配: DP + TP + PP

例如 64卡训练175B:
- TP = 8 (一个节点内)
- PP = 4 (跨节点)
- DP = 2 (64/8/4 = 2)

组合利用各策略优点
```

# Part 5: 总结

---

## 选型指南

| 模型大小 | 推荐策略 |
|----------|----------|
| <10B | DDP |
| 10B-50B | ZeRO-2/3 |
| 50B-200B | ZeRO + TP |
| >200B | 3D并行 |

---

## 核心要点

| 策略 | 核心思想 | 代价 |
|------|----------|------|
| DDP | 复制模型，分发数据 | 内存冗余 |
| ZeRO | 分片一切 | 通信增加 |
| TP | 切分层内矩阵 | 需要高带宽 |
| PP | 切分层 | Pipeline bubble |

---

## 常见误区

| 误区 | 正确理解 |
|------|----------|
| 更多卡总是更快 | 通信可能成瓶颈 |
| ZeRO-3最好 | 通信开销大，需权衡 |
| 只用一种并行 | 大模型需要组合 |

## Q&A

### Q: 什么时候用ZeRO-2 vs ZeRO-3？
**A**: ZeRO-2内存够用就用ZeRO-2，通信开销小。内存不够才用ZeRO-3。

### Q: FSDP和DeepSpeed哪个好？
**A**: 功能类似。FSDP是PyTorch原生，集成好。DeepSpeed功能更丰富，优化更激进。
