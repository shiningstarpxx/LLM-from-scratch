# Part 2: 训练内存四大组件

---

## 2.1 组件概览

```
训练内存 = 权重 + 梯度 + 优化器状态 + 激活值

7B模型:
┌──────────────────────────────────┐
│ FP32 主权重        28GB          │
│ FP16 工作权重      14GB          │
│ FP16 梯度          14GB          │
│ Adam 动量          28GB          │
│ Adam 方差          28GB          │
├──────────────────────────────────┤
│ 基础合计           112GB         │
│ + 激活值           16-48GB       │
├──────────────────────────────────┤
│ 总计              128-160GB      │
└──────────────────────────────────┘
```

---

## 2.2 为什么需要FP32主权重？

```python
# 混合精度训练流程:

# 1. FP32主权重 (高精度存储)
master_weights = torch.float32  # 28GB

# 2. 复制到FP16 (高速计算)
working_weights = master_weights.half()  # 14GB

# 3. FP16前向传播
output = model_fp16(input)

# 4. FP16反向传播
loss.backward()  # 梯度也是FP16

# 5. 更新FP32主权重
master_weights -= lr * gradient.float()

为什么？FP16精度不够累积小更新
```

---

## 2.3 Adam优化器状态

```python
# Adam公式:
m_t = β1 * m_{t-1} + (1-β1) * g_t      # 动量
v_t = β2 * v_{t-1} + (1-β2) * g_t²     # 方差
w_t = w_{t-1} - lr * m_t / (√v_t + ε)

# 每个参数需要存储:
# - m (动量): FP32, 4 bytes
# - v (方差): FP32, 4 bytes

# 7B模型:
# Adam状态 = 7B × (4 + 4) = 56GB

# 这是最大的内存开销!
```

---

## 2.4 激活值内存

```python
def estimate_activation(batch, seq_len, hidden, layers):
    """
    简化估算 (无checkpointing)
    """
    # 每层主要激活:
    # - 注意力输入/输出
    # - FFN中间激活
    # - 注意力矩阵 [batch, heads, seq, seq]

    per_layer = batch * seq_len * hidden * 4  # 约4倍hidden
    per_layer += batch * 32 * seq_len * seq_len  # 注意力矩阵

    total = per_layer * layers * 2  # FP16 = 2 bytes
    return total / 1e9  # GB

# batch=32, seq=2048, hidden=4096, layers=32
estimate_activation(32, 2048, 4096, 32)
# ≈ 48 GB
```

# Part 3: 推理内存与KV Cache

---

## 3.1 推理vs训练

```
推理不需要:
- 梯度 ❌
- 优化器状态 ❌
- 大部分激活 ❌

推理需要:
- 模型权重 ✓
- KV Cache ✓ ← 关键!
```

---

## 3.2 KV Cache公式

```python
def kv_cache_size(batch, seq_len, layers, heads, head_dim):
    """
    KV Cache = 2 × L × B × H × S × D × bytes
    """
    # K和V各一份
    size = 2 * layers * batch * heads * seq_len * head_dim * 2
    return size / 1e9  # GB

# LLaMA-7B: 32层, 32头, head_dim=128
kv_cache_size(1, 2048, 32, 32, 128)   # 1.0 GB
kv_cache_size(1, 8192, 32, 32, 128)   # 4.0 GB
kv_cache_size(1, 32768, 32, 32, 128)  # 16.0 GB
```

---

## 3.3 KV Cache的影响

```
7B模型推理:

seq=2K:  权重14GB + KV 1GB = 15GB  ✓ 单卡可行
seq=8K:  权重14GB + KV 4GB = 18GB  ✓ 单卡可行
seq=32K: 权重14GB + KV 16GB = 30GB ✓ 单卡可行
seq=128K: 权重14GB + KV 64GB = 78GB ⚠️ 需要大显存

长序列时，KV Cache > 模型参数!
```

---

## 3.4 GQA: KV Cache优化

```python
# 标准MHA: num_kv_heads = num_heads
# GQA: num_kv_heads < num_heads

# LLaMA-2 70B:
# num_heads = 64
# num_kv_heads = 8 (GQA)

# KV Cache减少: 64/8 = 8倍!

def kv_cache_gqa(batch, seq_len, layers, num_kv_heads, head_dim):
    size = 2 * layers * batch * num_kv_heads * seq_len * head_dim * 2
    return size / 1e9

# 70B with GQA, seq=4K:
kv_cache_gqa(1, 4096, 80, 8, 128)  # 2.6 GB (vs 21 GB without GQA)
```

# Part 4: 优化策略

---

## 4.1 减少优化器内存

```python
# 标准Adam: 56GB (7B模型)

# 8-bit Adam: 14GB (75%减少)
import bitsandbytes as bnb
optimizer = bnb.optim.Adam8bit(model.parameters())

# Adafactor: 0GB 额外状态
# 用梯度近似m和v
optimizer = transformers.Adafactor(model.parameters())
```

---

## 4.2 减少激活内存

```python
# Gradient Checkpointing
# 用重算换内存

# 无checkpoint: 48GB激活
# 有checkpoint: ~10GB激活 (重算增加30%计算)

model.gradient_checkpointing_enable()
```

---

## 4.3 分布式策略

```
ZeRO Stage 1: 分片优化器状态
ZeRO Stage 2: + 分片梯度
ZeRO Stage 3: + 分片参数

8卡ZeRO-3:
每卡内存 = 112GB / 8 = 14GB
```

# Part 5: 总结

---

## 核心公式

```
训练内存 = 16P + 激活
其中P是参数量 (bytes), 16 = 4(FP32主)+2(FP16)+2(梯度)+8(Adam)

推理内存 = 2P + KV_Cache
```

## Q&A

### Q: 为什么Adam必须FP32？
**A**: 动量和方差是累积量，FP16精度不够会累积误差。

### Q: 能用SGD省内存吗？
**A**: 可以，但收敛慢很多。Adam状态存储了有价值的历史信息。
