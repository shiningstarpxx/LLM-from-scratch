## 创新1：稀疏门控 (Sparse Gating)

<br>

```
┌─────────────────────────────────────────────────────────────┐
│                      稀疏门控机制                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│    传统门控（1991）：                                        │
│    ┌─────────────────────────────────────────┐              │
│    │ g(x) = softmax(W·x)                     │              │
│    │ 输出：[0.15, 0.20, 0.18, 0.12, ...]     │ ← 全部非零   │
│    │ 计算：所有N个专家                        │              │
│    └─────────────────────────────────────────┘              │
│                                                             │
│    稀疏门控（2017）：                                        │
│    ┌─────────────────────────────────────────┐              │
│    │ g(x) = SparseTopK(softmax(W·x), K)      │              │
│    │ 输出：[0, 0.55, 0, 0, 0.45, 0, ...]     │ ← 只有K个非零│
│    │ 计算：只有K个专家                        │              │
│    └─────────────────────────────────────────┘              │
│                                                             │
│    效率提升公式：                                            │
│    ┌─────────────────────────────────────────┐              │
│    │  参数量 = N × P    （N倍）               │              │
│    │  计算量 = K × C    （K倍）               │              │
│    │  性价比 = N / K    （N=128, K=2 → 64倍）│              │
│    └─────────────────────────────────────────┘              │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 创新2：Noisy Gating - 解决专家坍缩

<br>

```
┌─────────────────────────────────────────────────────────────┐
│                   专家坍缩的根本原因                         │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│    正反馈循环：                                             │
│                                                             │
│    Expert 1 偶然表现好                                      │
│          ↓                                                  │
│    获得更多 token                                           │
│          ↓                                                  │
│    更多训练 → 更强                                          │
│          ↓                                                  │
│    门控分数更高 → 选更多                                    │
│          ↓                                                  │
│    其他专家"饿死"                                           │
│                                                             │
├─────────────────────────────────────────────────────────────┤
│                   Noisy Gating 解决方案                      │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│    logits = W·x + ε·noise    （训练时加噪声）               │
│                                                             │
│    无噪声：E1=3.0, E2=2.9 → 总是选E1 → E2饿死               │
│    有噪声：E1=3.0±0.5, E2=2.9±0.5 → 有时选E2 → E2存活      │
│                                                             │
│    效果：打破确定性路由，促进探索                           │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 创新3：辅助损失 - 强制负载均衡

<br>

```
┌─────────────────────────────────────────────────────────────┐
│                      辅助损失机制                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│    目标：每个专家处理大约 1/N 的 token                       │
│                                                             │
│    定义：                                                   │
│    • Importance_i = 专家i的平均门控权重                     │
│    • Load_i = 专家i被选中的频率                             │
│                                                             │
│    辅助损失：                                               │
│    ┌─────────────────────────────────────────┐              │
│    │                   N                      │              │
│    │  L_aux = N × Σ (Importance_i × Load_i)  │              │
│    │                  i=1                     │              │
│    └─────────────────────────────────────────┘              │
│                                                             │
│    总损失 = L_main + α × L_aux    （α ≈ 0.01）              │
│                                                             │
├─────────────────────────────────────────────────────────────┤
│    均匀分布时：L_aux 最小                                    │
│    集中在一个专家时：L_aux 最大 → 被惩罚                    │
└─────────────────────────────────────────────────────────────┘
```

## 关键改进对比：2017 vs 2021

<br>

| 维度 | Shazeer 2017 | Switch 2021 | 改进原因 |
|:-----|:-------------|:------------|:---------|
| **Top-K** | K=2 | **K=1** | 最简单，计算最少 |
| **Gating** | Noisy + Softmax | **简单Softmax** | 减少超参数 |

| **架构** | LSTM | **Transformer** | 并行优势 |
| **规模** | 137B | **1.6万亿** | 12倍扩展 |

## 新问题：Top-1导致专家过载

<br>

```
┌─────────────────────────────────────────────────────────────┐
│                     专家过载问题                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│    Token路由示例（8个token，4个专家）：                      │
│                                                             │
│    Token:    [t1, t2, t3, t4, t5, t6, t7, t8]              │
│    路由到:   [E1, E1, E1, E1, E1, E2, E3, E3]              │
│                                                             │
│    Expert 1: 收到5个token → 过载！处理不过来                │
│    Expert 4: 收到0个token → 空闲！资源浪费                  │
│                                                             │
├─────────────────────────────────────────────────────────────┤
│                   解决方案：Capacity Factor                  │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│    capacity = (tokens / experts) × factor                   │
│             = (8 / 4) × 1.25 = 2.5 → 3                     │
│                                                             │
│    规则：每个专家最多处理3个token                           │
│    超出：直接跳过（残差连接）                               │
│                                                             │
│    代价：约5%的token被丢弃                                  │
│    收益：训练稳定，效率可控                                 │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## Q&A

<br>

### Q: MoE比Dense好在哪？
**A**: 相同计算下有更多参数，学到更多知识。本质是"参数换计算"的trade-off。

### Q: 为什么Attention不用MoE？
**A**: FFN占计算的2/3，MoE收益大。Attention占1/3且难以稀疏化。

### Q: MoE的缺点？
**A**: 推理时需加载所有专家参数，显存要求高。小batch效率优势不明显。
