## 符号表（核心符号速查）

<br>

| 符号 | 含义 | 符号 | 含义 |
|:----:|:-----|:----:|:-----|
| $x$ | 输入token向量 | $N$ | 专家总数 |

$$\text{MoE}(x) = \sum_{i \in \text{TopK}} g_i(x) \cdot E_i(x)$$

## 1.10 创新1：Noisy Gating - 解决专家坍缩

<br>

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                       专家坍缩的根本原因                                     │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│     正反馈循环 (Matthew Effect)：                                           │
│                                                                             │
│     Expert 1 偶然表现好                                                     │
│           ↓                                                                 │
│     获得更多 token                                                          │
│           ↓                                                                 │
│     更多训练 → 更强                                                         │
│           ↓                                                                 │
│     门控分数更高 → 选更多                                                   │
│           ↓                                                                 │
│     其他专家"饿死"                                                          │
│                                                                             │
├─────────────────────────────────────────────────────────────────────────────┤
│                       Noisy Gating 解决方案                                  │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│     logits = W·x + ε·noise      （训练时加噪声）                            │
│                                                                             │
│     无噪声：E1=3.0, E2=2.9 → 总是选E1 → E2饿死                              │
│     有噪声：E1=3.0±0.5, E2=2.9±0.5 → 有时选E2 → E2存活                     │
│                                                                             │
│     效果：打破确定性路由，促进探索                                          │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 1.11 创新2：辅助损失 - 强制负载均衡

<br>

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                         辅助损失机制                                         │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│     目标：每个专家处理大约 1/N 的 token                                     │
│                                                                             │
│     定义：                                                                  │
│     • Importance_i = 专家i的平均门控权重                                    │
│     • Load_i = 专家i被选中的频率                                            │
│                                                                             │
│     辅助损失：                                                              │
│     ┌─────────────────────────────────────────┐                            │
│     │                   N                      │                            │
│     │  L_aux = N × Σ (Importance_i × Load_i)  │                            │
│     │                  i=1                     │                            │
│     └─────────────────────────────────────────┘                            │
│                                                                             │
│     总损失 = L_main + α × L_aux    （α ≈ 0.01）                            │
│                                                                             │
├─────────────────────────────────────────────────────────────────────────────┤
│     均匀分布时：L_aux 最小                                                   │
│     集中在一个专家时：L_aux 最大 → 被惩罚                                   │
└─────────────────────────────────────────────────────────────────────────────┘
```

# Part 2: MoE数学原理

**核心问题**：MoE的数学本质是什么？如何精确描述稀疏计算？

---

## 2.1 MoE层的数学定义

<div class="math-box">

**定义 2.1 (MoE层)**：给定输入 $x \in \mathbb{R}^{d_{model}}$，MoE层的输出定义为：

$$\text{MoE}(x) = \sum_{i \in \mathcal{S}(x)} g_i(x) \cdot E_i(x)$$

其中：
- $\mathcal{S}(x) = \text{TopK}(G(x), K)$ 是激活的专家索引集合
- $g_i(x)$ 是专家 $i$ 的门控权重
- $E_i(x)$ 是第 $i$ 个专家网络的输出

</div>

---

## 2.2 稀疏门控的严格定义

<br>

**定义 2.2 (稀疏门控)**：

$$G(x) = \text{SparseTopK}(\sigma(x^T W_g), K)$$

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                         SparseTopK 操作定义                                  │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│                     ⎧  p_i                                                  │
│                     ⎪  ────────────    if i ∈ Top-K索引集                  │
│   SparseTopK(p,K)_i=⎨  Σ p_j                                               │
│                     ⎪  j∈TopK                                              │
│                     ⎩  0               otherwise                            │
│                                                                             │
├─────────────────────────────────────────────────────────────────────────────┤
│   关键性质：                                                                │
│   • 稀疏性：只有 K 个非零元素                                               │
│   • 归一性：所有非零元素之和 = 1                                            │
└─────────────────────────────────────────────────────────────────────────────┘
```

---

## 2.3 稀疏门控代码实现

```python
def sparse_gating(x, W_g, k):
    """
    稀疏门控的完整实现

    x: [d_model] - 输入token表示
    W_g: [d_model, num_experts] - Router权重
    k: int - Top-K值
    """
    # Step 1: 计算logits
    logits = x @ W_g                    # [num_experts]

    # Step 2: Softmax得到概率
    probs = softmax(logits)             # [num_experts]

    # Step 3: Top-K选择
    top_k_probs, top_k_idx = topk(probs, k)

    # Step 4: 重新归一化
    top_k_probs = top_k_probs / top_k_probs.sum()

    # Step 5: 稀疏化输出
    sparse_probs = zeros_like(probs)
    sparse_probs[top_k_idx] = top_k_probs

    return sparse_probs, top_k_idx
```

---

## 2.4 专家网络结构

<br>

<div class="math-box">

**定义 2.3 (专家网络)**：第 $i$ 个专家网络 $E_i$ 定义为：

$$E_i(x) = W_{i,2} \cdot \phi(W_{i,1} \cdot x)$$

其中 $\phi$ 是激活函数（GELU或SiLU）

</div>

```python
class Expert(nn.Module):
    """标准FFN专家实现"""
    def __init__(self, d_model, d_ff, activation='gelu'):
        super().__init__()
        self.w1 = nn.Linear(d_model, d_ff)    # 上投影
        self.w2 = nn.Linear(d_ff, d_model)    # 下投影
        self.act = nn.GELU() if activation == 'gelu' else nn.SiLU()

    def forward(self, x):
        h = self.act(self.w1(x))  # [B, S, d_ff]
        return self.w2(h)          # [B, S, d_model]
```

<div class="key-point">

**关键观察**：专家结构与Dense FFN完全相同，区别在于每个专家只看到路由到它的token子集！

</div>

## 3.2 解决方案1：Noisy Top-K Gating

<br>

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                         Noisy Gating 原理                                   │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   无噪声（确定性路由）：                                                     │
│   ─────────────────────                                                     │
│   Expert 1 得分: 3.0                                                        │
│   Expert 2 得分: 2.9                                                        │
│   → 总是选 Expert 1 → Expert 2 饿死                                        │
│                                                                             │
│   有噪声（随机探索）：                                                       │
│   ─────────────────────                                                     │
│   Expert 1 得分: 3.0 + noise₁ = 2.8 (这次)                                 │
│   Expert 2 得分: 2.9 + noise₂ = 3.2 (这次)                                 │
│   → 这次选 Expert 2 → Expert 2 存活！                                      │
│                                                                             │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   公式：logits = W·x + ε × softplus(W_noise·x)                             │
│                           ↑                                                 │
│                      可学习的噪声幅度                                        │
│                                                                             │
│   关键：噪声幅度是可学习的，模型自己决定什么时候需要更多探索                │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 3.3 Noisy Gating 代码实现

```python
def noisy_topk_gating(x, W_g, W_noise, k, training=True):
    """
    Noisy Top-K Gating (Shazeer 2017)

    x: [batch, d_model] - 输入
    W_g: [d_model, num_experts] - 门控权重
    W_noise: [d_model, num_experts] - 噪声权重 (可学习)
    k: int - Top-K
    """
    # Step 1: 计算基础logits
    logits = x @ W_g  # [batch, num_experts]

    # Step 2: 训练时加噪声
    if training:
        noise_stddev = F.softplus(x @ W_noise)  # 可学习的噪声幅度
        noise = torch.randn_like(logits) * noise_stddev
        logits = logits + noise

    # Step 3: Softmax + Top-K
    probs = F.softmax(logits, dim=-1)
    top_k_probs, top_k_idx = torch.topk(probs, k, dim=-1)

    # Step 4: 重归一化
    top_k_probs = top_k_probs / top_k_probs.sum(dim=-1, keepdim=True)

    return top_k_probs, top_k_idx
```

## 3.4 解决方案2：辅助损失（Auxiliary Loss）

<br>

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                         辅助损失机制                                         │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   目标：强制每个专家处理约 1/N 的 token                                     │
│                                                                             │
│   定义两个统计量：                                                          │
│   ─────────────────                                                         │
│   Importance_i = 专家i的平均门控权重（被\"看重\"多少）                       │
│   Load_i       = 专家i被选中的频率（实际\"干活\"多少）                       │
│                                                                             │
│   辅助损失公式：                                                            │
│   ┌─────────────────────────────────────────┐                              │
│   │                   N                      │                              │
│   │  L_aux = N × Σ (Importance_i × Load_i)  │                              │
│   │                  i=1                     │                              │
│   └─────────────────────────────────────────┘                              │
│                                                                             │
│   数学性质：                                                                │
│   ─────────────────                                                         │
│   均匀分布时：L_aux = K（最小值，如K=2时为2）                               │
│   完全集中时：L_aux = N（最大值，如N=8时为8）                               │
│                                                                             │
│   → 优化过程自动推动向均匀分布靠近！                                        │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 3.5 辅助损失代码实现

```python
def auxiliary_loss(router_probs, expert_indices, num_experts):
    """
    辅助损失 (Shazeer 2017)

    router_probs: [B*S, num_experts] - softmax后的概率
    expert_indices: [B*S, k] - 选中的专家索引
    """
    # Importance: 每个专家的平均门控权重
    importance = router_probs.mean(dim=0)  # [num_experts]

    # Load: 每个专家被选中的频率
    one_hot = F.one_hot(expert_indices, num_experts)  # [B*S, k, E]
    load = one_hot.sum(dim=1).float().mean(dim=0)     # [num_experts]

    # 损失: 惩罚集中分布
    aux_loss = num_experts * (importance * load).sum()
    return aux_loss

# 总损失
total_loss = main_loss + α * aux_loss  # α ≈ 0.01
```

<br>

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                         Router Z-Loss (ST-MoE 2022)                         │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   问题：训练后期Router logits可能爆炸                                       │
│   ─────────────────────────────────────────                                 │

│   Z-Loss解决方案：                                                          │

│                                                                             │
│   典型配置：                                                                │
│   total_loss = L_main + 0.01×L_aux + 0.001×L_z                             │
│                                                                             │

```

## 4.1 MoE层完整实现

```python
class MoELayer(nn.Module):
    def __init__(self, d_model, d_ff, num_experts, top_k, capacity_factor=1.25):
        super().__init__()
        self.num_experts = num_experts
        self.top_k = top_k
        self.capacity_factor = capacity_factor

        # N个专家网络
        self.experts = nn.ModuleList([
            Expert(d_model, d_ff) for _ in range(num_experts)
        ])

        # Router（简单线性层）
        self.gate = nn.Linear(d_model, num_experts, bias=False)

    def forward(self, x):
        """
        x: [batch, seq, d_model]
        """
        B, S, D = x.shape
        x_flat = x.view(-1, D)  # [B*S, D]

        # 1. 计算门控
        router_logits = self.gate(x_flat)  # [B*S, E]
        router_probs = F.softmax(router_logits, dim=-1)

        # 2. Top-K选择
        top_k_probs, top_k_idx = torch.topk(router_probs, self.top_k)
        top_k_probs = top_k_probs / top_k_probs.sum(dim=-1, keepdim=True)

        # 3. 计算辅助损失
        aux_loss = self._aux_loss(router_probs, top_k_idx)

        # 4. 专家计算
        output = self._compute_experts(x_flat, top_k_probs, top_k_idx)

        return output.view(B, S, D), aux_loss
```

## 4.2 高效专家计算：批量处理

```python
def _compute_experts_batched(self, x, probs, indices):
    """
    批量计算：按专家分组处理，避免Python循环

    关键优化：把路由到同一专家的token合并计算
    """
    output = torch.zeros_like(x)

    for expert_id in range(self.num_experts):
        # 找到路由到这个专家的所有token
        mask = (indices == expert_id).any(dim=-1)  # [B*S]
        if not mask.any():
            continue

        # 批量处理（一次matmul）
        expert_input = x[mask]  # [n, D]
        expert_output = self.experts[expert_id](expert_input)

        # 加权累加
        weight_mask = (indices[mask] == expert_id).float()
        weights = (probs[mask] * weight_mask).sum(dim=-1, keepdim=True)
        output[mask] += weights * expert_output

    return output
```

<div class="warning">

**关键点**：避免token级别的循环，改用专家级别的批量处理！

</div>

# Q&A (5 min)

---

## 常见问题

### Q1: MoE训练比Dense难吗？
**A**: 是的，需要处理负载均衡、训练稳定性。但有成熟方案（辅助损失+Z-Loss）。

### Q2: 为什么GPT-4据传是MoE？
**A**: 推测依据：参数量大但推理快、API成本可控。OpenAI未公开确认。

### Q3: MoE适合微调吗？
**A**: 可以，技巧：只调部分专家、更小学习率、考虑MoE+LoRA组合。

### Q4: Attention为什么不用MoE？
**A**: FFN占计算2/3，MoE收益大；Attention难以稀疏化且只占1/3。
